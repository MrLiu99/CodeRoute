# 固定版本交付评测（2026-09-29）

## 本轮范围

目标是核心功能齐全、真实动态路径有证据、固定版本评测、可解释的成功失败，以及可复现的使用文档。在此基础上提高成功率，不要求复杂案例百分之百成功。

本轮只运行 `configs/release-suite.json` 中的 14 个案例，Hybrid 每例一次，总计最多 14 次真实修复。开始后不修改执行源码、案例或配置，不选择性重跑，不追加复杂案例实验。自动生成测试保留在 `configs/reliable-tools.json`，作为实验功能；本轮 `configs/release.json` 不启用该功能。公开测试、逐项需求审查、当前 revision 门禁和独立验收仍保留。

## 本轮修改

- Developer 直接获得最新实际测试结果，使 Tester→Developer 的动态路径也有失败信息，不依赖 Debugger 必然介入。
- 启用 `role_context_refresh`：当角色对话超过上下文上限的 80%，从当前工作副本重新组装上下文，保留进入角色时的测试/审查反馈、最近三次动作摘要和剩余回合。旧工具对话整组替换，避免断开的原生调用 ID。角色回合与总调用计数不重置；新上下文本身过大仍按原上限停止。
- 保留原生函数调用、有限协议纠正、批量编辑和开发预算交接；补充一般性的状态转换检查提示，不把外部验收答案放进角色上下文。
- 加入显式 `--suite` 清单，统一评测分布在不同目录的案例；批次记录实际案例路径和内容指纹。
- 转账案例新建 `12_atomic_transfers_v2`：仅明确未知账户抛 KeyError、非正金额和余额不足抛 ValueError。源代码、公开测试、独立验收与参考修改保持原样，旧版案例和历史成绩不覆盖。当前清单包含 14 个任务；磁盘多保留了一个旧版本，并非增加一个独立任务。

成功要求：Harness 完成测试与审查、独立验收通过、原始案例未改变。不能把补丁独立验收通过但流程中断算成功。该批次是自建案例上的一次功能回归，不是多次重复的稳定性估计，也不是四策略对照；不能直接与不同版本的历史数字作因果比较。

## 唯一失败的解释

流式案例实际路径：Analyzer→Developer→Tester（5 通过、2 失败）→Debugger→Developer→Tester（7/7 通过）→Reviewer 接受。两次测试对应不同代码 revision；公开测试恢复是真实模型行为。事后独立验收 `test_all_two_way_splits` 和 `test_public_helper_contracts` 失败，因此整次任务仍失败。

`decode_chunks` 使用增量解码，但在第一次解码返回空字符串时就把 `first` 改为 false。输入 `[b'\xef', b'\xbb\xbf', ...]` 时，BOM 在后续块才解出，已经错过移除机会。两个失败测试均受到这个问题影响。Reviewer 的需求清单和源码引用检查通过，却没有识别这条路径，是语义审查漏判。

另外，对保存补丁进行不调用模型的最小复现，发现 `parse_records(['"a"', '"b"\n'])` 应与单片段 `parse_records(['"a""b"\n'])` 一样产生 `[['a"b']]`，实际前者抛出 ValueError。代码只向当前片段内查看第二个引号，缺少跨片段转义引号状态。这个诊断结果不能冒充原独立测试的额外失败计数。

复现结果保存在批次的 `offline_diagnosis.json`。没有修改该运行的补丁、测试或评分，也没有再次调用模型修正它。本次复杂任务消耗 24 次调用、约 92.4 秒，失败不是预算耗尽，而是边界语义错误未被公开测试和 Reviewer 拦住。

新版无费用演示命令也实际通过：`runs/release-demo/20260929-162713-895d6399`，7 个角色步骤、公开测试 5/5。它是 mock，不计入真实模型成功率。

## 核对、用量与完成边界

批次 `audit.json` 已确认：14 个唯一组合完整，执行源码指纹和实际配置与当前版本一致，全部案例指纹不变，受保护测试未修改，外部验收测试未出现在修复工作区，Harness 成功记录的测试/审查 revision 一致，各类 token 分项相加匹配。文本产物扫描未发现本地配置的 API 密钥。旧版转账源码与测试和 v2 逐字节相同；仅需求文本与版本元数据有变化。

总计 **106 次模型调用**：角色 85、主模型路由 5、轻量路由 16。提供商返回输入 **326,814 token**、输出 **43,530 token**；无缺失 usage 的调用。各任务 Harness 耗时合计约 **328.4 秒**，不含事后独立验收和工程检查，不能当作账单或端到端总耗时。一次角色协议错误被纠正；没有任务因预算耗尽或协议错误终止。

上下文刷新与 Developer 预算交接本批次均未触发，只有工程测试证据，不能将本次成绩归因于它们。多项配置、提示与案例规格发生改变，且没有固定版本对照，因此也不能声称某项修改单独提高了成功率。

本轮完成了第一版的功能收敛、完整固定回归、动态路径证据整理和复现文档。仍保留以下限制：复杂跨片段状态机可漏修、Reviewer 有误接受、轻量函数格式不稳定、模型置信度未校准；没有新版多策略效果比较，没有新案例上的泛化验证。每例仅一次，命令和配置可复现，模型结果不保证逐次一致。该版本可作为有明确限制的展示原型交付，不能宣称生产级可靠。

按计划完成 14 次后停止追加 API 实验。后续若继续优化，优先分别处理轻量函数名约束和跨片段语义验证；应另开固定评测批次，保留本轮成绩，不把人工修补后的案例算作模型成功。
