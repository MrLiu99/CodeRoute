## 完成标准

1. 原文需求清单在分析、开发、审查间传递。分析与审查提交必须覆盖所有编号，审查不能带未满足/不确定条目通过，证据引用必须匹配当前文件。新增与既有自动化测试通过。
2. 普通修复通过最终验收，且至少一条真实测试失败 → Debugger → 新补丁 → 测试与审查通过 → 独立验收通过的记录。模拟调用不算。
3. README 指向统一的安装、配置、示例、架构、结果和限制说明，命令可复现。

需求编号来自原文按句号、分号和换行切分，不是模型随意选择的需求子集。一个条目可能有多项义务，Reviewer 必须解释全部义务。机械校验只证明条目齐全、引用存在，不能形式化证明语义正确；独立验收仍是必要条件。
