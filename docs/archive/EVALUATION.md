## 唯一失败

案例 `09_invoice_units`，策略 `dynamic`（Rule + LLM）：

- Developer 的最终补丁通过了公开测试和独立验收。
- Reviewer 多次返回多个 JSON 对象，违反单回合单 JSON 对象协议；另一次读取了不存在的 `test_invoice.py` 路径。
- Reviewer 在 8 回合内没有提交审查结果，因此结束状态为 `budget_exhausted`。
- 这次运行记为失败，没有重试或用通过的补丁替换失败记录。

证据目录：`09_invoice_units-dynamic-r1/` 下的 `trajectory.json`、`final_state.json` 和 `acceptance_run/result.json`。
这是角色协议与上下文使用问题，不能直接归因为路由策略较差。

## 实验设置

- 主模型：`deepseek-flash`，用于 Analyzer / Developer / Debugger / Reviewer 和主模型路由。
- 轻量服务：OpenRouter，模型 `qwen/qwen3-30b-a3b-instruct-2507`。未使用 Jev。
- Tester 为确定性 pytest 执行组件，不调用模型。
- 置信度阈值 0.65；该分数为模型自报值，未在此数据集上校准。
- 每次运行最多 16 个角色步骤，单角色最多 8 个模型回合，总模型调用上限 48，总耗时上限 600 秒。
- 四种策略共用同一组模型配置、角色提示、工具、测试和预算；模型策略顺序随案例轮换。
- 每次从原始缺陷建立独立副本。Agent 看不到 `holdout/` 或参考修改；独立验收在第二个副本运行。
- 数据集覆盖空白输入、零边界、分页、可变默认值、缓存假值、稳定去重、异常重试、加权平均、跨文件单位转换、库存恢复。
- 模型采样不保证确定性；每个案例每种方法仅一次，没有置信区间或显著性检验。

## 可以与不可以得出的结论

这次运行验证了完整执行链、实际轻量服务调用、统计和独立验收管线。规则和轻量决策减少了本轮主模型控制调用，但不等于所有任务上都更快、更便宜或更可靠。

数据集只有 10 个很小的自建项目，四种策略没有产生不同的成功角色路径：都是 Analyzer → Developer → Tester → Reviewer。Debugger 调用为 0，低置信度升级为 0。失败恢复、复杂重新定位和置信度阈值收益仍只有其他模拟测试或单独功能测试支持，不能由本批次证明。

Fixed Workflow 在本轮平均耗时和总 token 上最低，符合简单案例不需要额外控制推理的特点。Hybrid 比 LLM Router 少用了主模型路由调用，但其端到端耗时仍高于 Fixed Workflow 和 Rule + LLM。本轮不支持“Hybrid 全指标最好”的表述。

## 完整性与恢复记录

会话切换期间原进程结束：15 条结果已汇总，第 16 次修复完成但验收未汇总。
`scripts/resume_evaluation.py` 从已有产物恢复，只重跑中断的验收，之后执行剩余 24 次修复。没有重复已完成的模型调用。恢复脚本与恢复时间分别记录在 `resume-*.json`。

最终核对确认：40 个唯一 case/method/repeat 组合齐全；数据集指纹与执行源码指纹不变；所有成功记录的测试、审查和代码 revision 一致；角色、主路由、轻量调用的 token 与总量一致；运行产物未发现本地 API 密钥。

批次保存的证据包括：

- `experiment.json`：模型配置、预算、案例指纹和方法列表。
- `code_fingerprints.json`：运行源码指纹。
- `results.json/csv`：每次运行的成功条件、退出原因、用量和路径。
- `summary.json/csv`、`report.md`：分策略汇总。
- `audit.json`：40 条记录的最终完整性核对。
- 每个 run 的模型响应、路由决策、工具观测、Git diff、测试日志及独立验收报告。

这些原始运行产物默认保存在本地 `runs/`，由 Git 忽略；本文件是可提交的结果摘要。

## 复现

```powershell
# 只验证缺陷与参考修复，不调用模型
python evaluate.py --config configs/default.json

# 新建完整批次，会产生新的模型调用
python evaluate.py --live --max-runs 40 --config configs/default.json

# 原进程确认结束后，恢复已存在批次；不要和原进程并行运行
python scripts/resume_evaluation.py runs/eval-20260928-170329-d6c06156
```

恢复不会重新跑已汇总的记录；如果某个修复本身没有留下最终产物，会明确报错，而不静默重试并掩盖中断记录。
